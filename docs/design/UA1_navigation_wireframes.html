1. Navigation map

One lane per role. Every role signs in on the same login screen and lands on its own home screen. Click a box to jump to its wireframe.

Student
Login→ Opportunity list→ Opportunity detail→ Apply form→ My applications (status timeline)→ My placement + learning goals→ Weekly check-in form
Coordinator
Login→ Needs-action queue (home)→ Pending opportunities| Applications + recommendations→ Decision form| Placements + overdue check-ins
Organization rep / Mentor
Login→ My opportunities (home)→ Draft opportunity form| Applicants + recommend| Assigned check-ins + feedback

"→" = goes to next screen. "|" = sibling screen reached from the same home/menu. Every screen also has the role's top menu and an in-app notifications link.

6. UI rules for all screens

  • Status labels are always words (SUBMITTED, UNDER REVIEW, SHORTLISTED, SELECTED, DECLINED, ACTIVE, OVERDUE), never colour only.
  • Same status names in UI, database, DFD and tests (to be fixed with Kunal's state rules, KAN-18).
  • Every form has visible labels, clear error text next to the problem, and works with keyboard only.
  • Every list has an empty state. Pages reflow to one column on mobile width.
  • Each role sees only its own data: student = own applications, rep = own organization, mentor = assigned students.
