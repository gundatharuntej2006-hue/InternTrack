1. Architecture (one server-rendered Django app)

flowchart TB U["Browser: Student / Coordinator / Org rep-Mentor"] MW["Middleware: session, CSRF, security headers, login rate limit"] V["Views + forms: validate input"] P["Permission layer: role + ownership, default deny"] SV["Services: opportunity, application, placement, check-in, queue, notifications"] DB[("PostgreSQL: 12 tables from UA-2")] T["Templates: accessible HTML, little JS"] U -- "HTTPS: pages + form POST" --> MW --> V --> P --> SV SV -- "ORM, transaction.atomic" --> DB V --> T -- "HTML response" --> U
LayerResponsibilityRule
BrowserShows pages, sends formsNo business logic in JavaScript
MiddlewareSession cookie, CSRF token, HTTPS headers, login rate limitSecure + HttpOnly cookies (NFR1)
Views + formsRead request, validate fields, pick templateNever trust ids for the actor; take user from session
Permission layerCheck role and ownership for every object (UA-2 matrix)Deny by default; 404 for other users' objects
ServicesState changes, events, placement creation, overdue calculation, noticesEach state change = one transaction with its event
PostgreSQLAll data, constraints, indexesOnly store; no files in MVP

8. Sequence diagrams

8.1 Org rep submits, coordinator publishes (FR2, FR3)

sequenceDiagram
  actor R as Org rep
  participant V as opportunities views
  participant S as opportunity service
  participant DB as PostgreSQL
  actor C as Coordinator
  R->>V: POST new opportunity (action=save)
  V->>S: save_draft(form)
  S->>DB: INSERT Opportunity (DRAFT)
  R->>V: POST edit (action=submit)
  V->>V: OpportunityForm(submitting=True).is_valid()
  V->>S: submit(opportunity)
  S->>DB: DRAFT to PENDING_REVIEW, OpportunityEvent, Notification OPP_SUBMITTED
  C->>V: POST approve
  V->>S: approve(opportunity, coordinator)
  S->>DB: PENDING_REVIEW to PUBLISHED, event, Notification OPP_PUBLISHED to reps and students
  V-->>C: redirect to review list with message

8.2 Student applies (FR4, FR5)

sequenceDiagram
  actor St as Student
  participant V as applications views
  participant S as application service
  participant DB as PostgreSQL
  St->>V: GET apply page
  V->>DB: opportunity PUBLISHED and deadline not passed?
  St->>V: POST ApplicationForm
  V->>S: apply(student, opportunity, data)
  S->>DB: BEGIN, check deadline and unique(student, opportunity)
  alt already applied or closed
    S-->>V: error
    V-->>St: form error, nothing saved
  else ok
    S->>DB: INSERT Application (SUBMITTED), StatusEvent, Notification APP_SUBMITTED, COMMIT
    V-->>St: redirect to My applications
  end

8.3 Recommendation, decision and placement (FR6, FR7)

sequenceDiagram
  actor R as Org rep
  actor C as Coordinator
  participant V as views
  participant S as application service
  participant DB as PostgreSQL
  R->>V: POST recommend (Shortlist, Select or Decline + rationale)
  V->>S: recommend(application, rep)
  S->>DB: INSERT Recommendation, Notification RECOMMENDATION_ADDED
  C->>V: POST decide
  V->>S: decide(application, new_status, reasons, goals)
  S->>DB: BEGIN, lock application, check allowed move and recommendation exists for Select
  alt Selected
    S->>DB: SELECTED + event, INSERT Placement (ACTIVE, mentor = opportunity.mentor) + 2-3 LearningGoals
    S->>DB: Notification STATUS_CHANGED and PLACEMENT_CREATED, COMMIT
  else Declined, Shortlisted or Under Review
    S->>DB: new status + event (public reason, internal note), Notification STATUS_CHANGED, COMMIT
  end
  V-->>C: redirect to applications list

8.4 Weekly check-in and mentor feedback (FR8, FR9)

sequenceDiagram
  actor St as Student
  actor M as Mentor (org rep)
  participant V as placements views
  participant DB as PostgreSQL
  St->>V: POST check-in
  V->>DB: placement ACTIVE and no check-in this week?
  V->>DB: INSERT CheckIn (week_start)
  M->>V: GET mentor check-ins
  V->>DB: check-ins where placement.mentor = M
  M->>V: POST feedback
  V->>DB: INSERT Feedback (mentor = placement.mentor), Notification FEEDBACK_ADDED
  St->>V: GET my placement
  V-->>St: check-ins with feedback, mentor name and date
